# Gatekeeper: Threshold Optimization Methodology (NHWRSF & NINOS2)

## Status

Proposed

## Context

In ADR 0003, the Gatekeeper's transient handling was overhauled to use a dynamically-adaptive 5-state machine driven by two primary DSP metrics:

- **NHWRSF** (Normalized Half-Wave Rectified Spectral Flux) for onset detection.
- **NINOS2** (Normalized Identification of Note Onset based on Spectral Sparsity) for tonal stability gating.

During the initial implementation, arbitrary threshold values were selected as starting points:

- `nhwrsf_threshold = 0.5`
- `ninos2_stability_threshold = 10.0`

While these arbitrary values happened to perform flawlessly across all 87 offline acoustic piano recordings (`diagnostics/key_*`), they are not mathematically grounded. To guarantee robust performance in live, noisy environments across different hardware, these thresholds must be rigorously optimized.

## Optimization Goals & Methodology

The goal is to replace the "lucky guess" thresholds with statistically derived values using the `diagnose_gatekeeper` telemetry.

### 1. NHWRSF Onset Threshold

**Objective:** High enough to reject sympathetic string resonance and ambient noise spikes, but low enough to reliably trigger on the softest possible ($ppp$) hammer strike across all 88 keys.

**Methodology:**

1. Parse the `gatekeeper.csv` telemetry for all 87 diagnostic keys.
2. For each key, extract the peak `nhwrsf` value that occurred during the actual hammer strike (when `is_new_onset` is true or immediately preceding the transition to `Stable`).
3. Find the global minimum peak NHWRSF across the entire keyboard (this represents the softest/weakest strike in the dataset).
4. Set the `nhwrsf_threshold` slightly below this global minimum to ensure a 100% catch rate while maximizing headroom against noise.

### 2. NINOS2 Stability Threshold

**Objective:** High enough to reject broadband transient noise (like dropping a book, speech, or coughing) but low enough to immediately latch onto the sparse harmonic structure of the fastest-decaying treble notes.

**Methodology:**

1. Generate a dataset of non-musical, broadband noise events (clapping, speech, dropping items, HVAC rumble).
2. Run these non-musical events through `diagnose_gatekeeper`.
3. Extract the maximum `ninos2` score generated by any of these broadband noise events.
4. Verify that the minimum `ninos2` score during the `Stable` phase of all 87 acoustic piano keys is significantly higher than the noise ceiling.
5. Set `ninos2_stability_threshold` at a safe margin between the highest non-musical noise score and the lowest valid piano sustain score.

## Consequences

- Replaces magic numbers with mathematically proven constants.
- Ensures the Gatekeeper remains bulletproof against false onsets and non-musical room noise.
- Provides a reproducible optimization script that can be re-run if the FFT size or sample rate is changed in the future.
